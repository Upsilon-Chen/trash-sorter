## 二、P0：三件必做的事

### P0-1 修掉数据泄漏，产出三组对比数字 ⭐ 最重要

**问题有两个：**

1. **增强图与原图混在同一个池子里随机划分**（这是我加的增强功能引入的）。
   现在 1974 张里 **1023 张是增强图（52%）**，`paper_x.jpg` 可能在训练集、
   而它的旋转版 `paper_x_r90.jpg` 落在验证集 —— 验证集里出现了训练图的"近亲"。
2. **同一机位连续抓拍的图本身就高度相似**，随机划分同样会泄漏。

**第三个问题**：每次「生成数据集」都重新随机划分 → **两次训练的指标不可比**。

**方案（按顺序做）：**

| 步骤 | 做法 | 说明 |
| --- | --- | --- |
| 1 | **按源图分组划分**：增强图必须与它的源图进同一侧 | 从文件名去掉增强后缀得到"组 id" |
| 2 | **按抓拍场次分组**（可选但更严谨）：同一物体/同一时段的连续抓拍归为一组 | 用文件名里的时间戳 |
| 3 | **固定划分**：划分种子写进配置，保证可复现 | 否则指标不可比 |
| 4 | **独立测试集**：换时间/换光照单独拍 100~150 张，只做最终评估 | 这才是真正的泛化性能 |
| 5 | 三组数字进报告 | 随机划分 → 分组划分 → 独立测试集 |

**预期**：mAP50 会从 0.99 掉下来。**掉下来才是好事** —— 说明你找到了并修掉了一个真实缺陷，
这比一个漂亮的 0.99 有说服力得多（老师多半会问"为什么这么高"）。

### P0-2 演示可靠性

| 保险 | 做法 | 覆盖的风险 |
| --- | --- | --- |
| **录像回放模式** | 摄像头源支持"视频文件"（把一段托盘录像当输入） | 摄像头坏了、教室光线不对、忘带设备 |
| **备用录屏 + GIF** | 提前录一段"完美流程" | 现场彻底崩了也能切视频讲 |
| **演示前热身** | 提前 20 分钟开机跑通一遍，舵机回中、托盘清空、确认串口号 | 90% 的现场问题都是没热身 |
| **手动下发兜底** | 识别失败时当场用「手动发送测试分类」补一次 | 反而显得系统考虑周全 |

### P0-3 把验证脚本收进 `tests/`

开发过程中验证过：旋转矩阵的**像素级一致性**、多目标四种策略、并发拉流稳定性、
认领机制与过期、背景差分精度、增强幂等与清理安全……**共 200+ 条断言，写完就删了**。
整理成 `tests/`（`pytest`）放进仓库，是**投入最小、信号最强**的一件事：

```
tests/
├── test_augmenter.py        # 标注换算的像素级一致性 + 代数性质
├── test_pipeline_multi.py   # 多目标四策略 + 稳定帧确认
├── test_annotator.py        # 标注读写/认领过期/背景差分/数据集构建
├── test_camera_concurrency.py  # 设备锁串行化（并发不崩）
└── test_api_smoke.py        # 用 TestClient 跑一遍主要接口
```

  把"改了什么 → 指标怎么变"对上，就是现成的实验章节。

  现在只知道 ESP32 单次循环约 3 秒，整链路没有数字。
- **P1-4 类别均衡**：`tableware` 只有 32 张，必是短板。演示前把每类原图补到 100 张以上。

  "托盘被误识别"的关键数据，建议补 50~200 张（用「连拍 8 帧取中值」设参考图后批量抓拍）。
- **P1-6 自动标注一致率**：抽 50~100 张，比较"背景差分自动标注"与"人工修正后"的 IoU 一致率。
  这是全项目最有原创性的量化指标（固定机位下的零人工标注）。
- **P1-7 README 截图/GIF**：见[第九节](#九dsh-插件调研结论)，DSH 里有录 GIF 的技能可用。

## 五、不建议做的事

| 不做 | 理由 |
| --- | --- |
| 用户系统 / 登录鉴权 / 权限 | 课程项目不加分，还引入一堆坑；局域网协作用私有网络就够 |
| Docker / K8s / 数据库 | 现在的文件 + 内存方案够用，换存储只增加演示风险 |
| 拆微服务 / 多摄像头调度 | 单机单相机就是这个题目的形态，拆分是"为架构而架构" |
| 任意角度数据增强 | 会把标注框撑大、混进背景，污染数据（现在的取舍本身就是加分点） |
| 换成更大的模型 / 上 Transformer | 8 GB 显存 + 单件分拣场景，yolov8n 足够；换了还讲不清收益 |
| 重写 antd 组件做"完全自定义 UI" | 工作量爆炸、易出 bug；用改造 token + 局部强化更划算 |

## 六、答辩问答准备（12 问）

| # | 老师可能问 | 建议怎么答 |
| --- | --- | --- |
| 1 | 准确率多少？ | 报 P/R/mAP50/mAP50-95 与每类 AP，**主动说明**验证集是随机划分、存在近重复，所以偏高；再给修复后的数字 |
| 2 | 验证集怎么划分？增强图会泄漏吗？ | 老实说"会，这是已知缺陷"，讲三组对比实验与修复方案（P0-1） |
| 3 | 1974 张够吗？ | 讲每类分布 + `tableware` 只有 32 张的问题 + 缓解手段（增强、优先补拍） |
| 4 | 和现成方案比，创新在哪？ | 三点：①**固定机位下背景差分零人工标注**（最好有一致率数据）②**多目标决策策略**（物理约束下必然分错，只决定牺牲谁）③**自采自标自训的完整闭环** |
| 5 | 实时性如何？ | 给端到端数字（P1-3）；ESP32 单次循环约 3 秒，检测 FPS 界面上有 |
| 6 | 为什么只做 90° 旋转？ | 检测框是轴对齐矩形，90° 整数倍才能**精确换算**；任意角度会把框撑大混进背景（**能体现思考深度**） |
| 7 | 同时放两件不同类的垃圾怎么办？ | 讲物理约束（一次倾倒只走一个方向）+ 四种策略 + 为什么默认有害垃圾优先 |
| 8 | 程序崩了/摄像头掉线怎么办？ | 讲看门狗自愈、设备锁防并发原生崩溃、faulthandler 留证据 |
| 9 | 怎么会把托盘认成纸张？怎么解决的？ | **整个项目最精彩的一段**：定位到"整图标注污染训练数据 + 白色纸板背景"的根因链，再给四种对策 |
| 10 | 为什么用 `classes.json` 做两层映射？ | 识别类别与物理桶解耦，加类别只改配置不动主流程（有 7 类→4 桶实例） |
| 11 | 硬件怎么接的、舵机怎么标定？ | 提前准备接线图与 PWM 脉宽↔角度标定过程 |
| 12 | 如果重做一遍会怎么改？ | 按"从一开始就采背景图 + 分组划分 + 每类均衡采样"回答，体现反思 |

## 八、UI 风格美化方案

### 8.1 现状诊断

先纠正一个判断：**现在的界面不丑，是"太素"**。当前基础其实很规范：

```ts
// frontend/src/main.tsx
colorPrimary: '#12b76a'    // 环保绿，已经是品牌色
borderRadius: 10, fontSize: 13, colorBgLayout: '#f2f5f7'
```

```css
/* frontend/src/styles.css */
--brand:#12b76a  --ink:#101828  --ink-soft:#475467
--muted:#98a2b3  --line:#e4e7ec  --bg:#f2f5f7
```

这套值就是设计系统里常见的"干净浅色 SaaS"配色。**"简单"的真实原因有五条：**

| # | 症状 | 后果 |
| --- | --- | --- |
| 1 | **没有视觉焦点** | 所有卡片、标签、表格视觉权重一样，眼睛不知道该看哪 |
| 2 | **数据没被可视化** | 识别结果、分拣计数全是文字 + Tag + 表格，缺少图表/仪表感 |
| 3 | **没有品牌记忆点** | 只有 ♻️ emoji，没有 Logo、没有特色强调元素 |
| 4 | **几乎没有动效** | 只有 antd 默认过渡，状态切换是"硬切" |
| 5 | **声明了字体但没引入** | `Inter`/`JetBrains Mono` 没自托管 → 实际回落到系统字体，数字不对齐（仪表盘最忌这个） |

另外两个**演示场景**问题：
- **只有浅色模式**：教室投影时浅灰底容易发灰、对比弱；
- **没有"演示态"**：没有适合投屏的大屏视图。

### 8.2 三个风格方向

#### 方向一：深色科技仪表盘（最出彩，推荐做主题之一）

```
背景 #0B1418 / 卡片 #151F26 / 边框 rgba(255,255,255,.08)
主色 #12B76A（环保绿，保留）  数据强调 #22D3EE（青）
警示 #F79009  危险 #F04438  主文字 #E6EDF3  次文字 #8B9AA8
效果：卡片 1px 主色微描边 + 轻微外发光；数字用等宽大字
```
- ✅ 与摄像头预览（本来就是深色画布）自然融合；投影对比强；"监控系统"既视感
- ⚠️ 教室灯光很亮时暗部会糊 → 所以要做成**可切换主题**，现场按环境选
- 工作量：**约 1 天**（antd `theme.darkAlgorithm` + token 覆盖 + 局部 CSS）

#### 方向二：精炼浅色 + 强数据可视化（最稳，建议打底）

保持浅色，把力气全花在**信息层级与图表**上：
- 4 个大类分拣计数 → 环形/条形图（手绘 SVG，不引依赖）
- 每个识别结果 → 一条置信度细进度条（颜色按类别）
- 近 30 次分拣 → 迷你折线/时间线
- 识别结果区做成"大号主结果卡"（类别名 32px + 置信度 + 桶位），其余降级为次要信息
- 工作量：**1~2 天**，风险最低，投影最安全

#### 方向三：演示大屏模式（最抓眼球，可选）

在方向一基础上加一个全屏视图：超大字号 + 4 个桶的状态卡 + 实时计数 + 摄像头画面占 2/3。
复用现有 WebSocket 数据，**不需要动后端**。
- ✅ 答辩现场效果最好
- ⚠️ 是"包装"不是"功能"，只在前两个方向做完后再考虑
- 工作量：**约 1 天**

**推荐组合**：方向二打底（稳）→ 方向一作为可切换主题（亮点）→ 时间够再做方向三。

### 8.3 施工清单（按优先级）

| 层级 | 具体做法 | 工作量 |
| --- | --- | --- |
| **信息层级**（最重要） | 每屏只留 1 个"主视觉"：控制台是识别结果，标注页是画布；其余卡片降一档（更小字号、更淡边框） | 0.5 天 |
| **设计令牌打通** | 用 antd 的 `cssVar: true` 让 token 自动生成 CSS 变量，样式表里统一用 `var(--ant-color-primary)`，**一处改全站变** | 0.5 天 |

### 8.4 两个容易被忽略的专业细节

1. **对比度**：`--muted #98a2b3` 在白底上对比度约 **2.6:1**，低于 WCAG AA 要求的 4.5:1。
   次要文字改用 `#667085`（约 4.8:1）更稳。DSH 里有 `a11y-debugging` 技能可以逐项核查。
2. **中文排版**：中文行高要比英文大（1.6~1.7），标点避免中英混排；
   投影场景下正文字号不要小于 13px、关键数字不小于 20px。

### 8.6 风险提示

- **别重写 antd 组件**：改造 token + 局部 CSS 能拿到 80% 的效果，重写要付出 5 倍代价；
- **优先级别搞反**：信息层级 > 配色 > 图表 > 动效。很多同学先加动效，结果更乱；
- **每改一版就截图存一份**，方便回退（也是给报告准备素材）。

## 九、DSH 插件调研结论

在 DSH 仓库（`D:\dsh\deepseek-harness`）里实际查过：

| 查了什么 | 结论 |
| --- | --- |
| 技能目录 `.agents/skills/*` | 12 个技能：代码审查、文档、性能、简化、CI 可靠性、翻译、推送前检查、**录浏览器 GIF** 等 —— **没有 UI/设计/主题类技能** |
| 客户端插件系统（`apps/web` 的 plugin-manager / install-registry） | 有插件体系，但它的作用是**给 DSH 自己的 Web GUI 加功能**，改不了你项目的界面 |
| npm 依赖里的 `chrome-devtools-mcp/skills/*` | 有 `a11y-debugging`、`debug-optimize-lcp` 等**给页面做无障碍/性能体检**的技能；本次会话未挂载为工具 |

**所以：没有"UI 美化插件"可以直接用。** 但有两件间接能帮上忙的：

1. **`record-browser-gif` 技能 + 仓库里的 Playwright** → 可以自动打开你的页面、录一段操作 GIF，
   正好用于 P1-7（README 演示动图）。
2. **`skill-office`（docx/pptx/xlsx）** → 如果最后要交报告或做 PPT，可以直接生成 Office 文档。

需要的话我可以试着在当前会话里加载这两个技能；加载不了的话，用 Playwright 直接写脚本也能达到同样效果。
